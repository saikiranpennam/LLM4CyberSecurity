Fine-Tuning Microsoft phi-2 on CVE Data: Reinforcing Computer Security with Language Models

An account of supervised fine-tuning, quantised adaptation, and structured evaluation of a small language model on the Common Vulnerabilities and Exposures corpus.

Author — Saikiran Pennam
Model — microsoft/phi-2
Dataset — new_cves_pps
Method — QLoRA · SFT
Abstract

This paper describes a pipeline for fine-tuning Microsoft's phi-2 language model on a curated dataset of Common Vulnerabilities and Exposures (CVE) records, with the aim of producing a domain-specialist model capable of accurately describing software vulnerabilities on demand. We employ 4-bit quantisation via BitsAndBytes, parameter-efficient adaptation via LoRA, and evaluation via ROUGE overlap metrics on a held-out validation set.

I. Introduction

The field of cybersecurity demands rapid, accurate recall of vulnerability information. A practitioner querying the nature of CVE-2012-0782 should receive a precise, technically grounded response — not a hallucinated account. General-purpose language models, trained on broad internet corpora, frequently fall short of this standard. They may confabulate identifiers, mix up affected versions, or describe mitigations that do not exist.

Fine-tuning on domain-specific instruction data is among the most cost-effective methods of improving LLM factuality within a narrow field.

The experiment described here takes a direct approach: gather a structured CVE dataset, format it as instruction-response pairs, and fine-tune a compact but capable base model — Microsoft's phi-2 — using modern parameter-efficient techniques that make the process feasible on a single GPU. The result is a specialist model, phi2-FT-improved-cves-data, deployed to the Hugging Face Hub for evaluation and inference.

Each row is formatted into a single string template before training. The [INST] and [/INST] tokens demarcate the instruction from the expected response — a convention that allows the model to learn the boundary between prompt and completion cleanly.

def format_rows(row):
    instruction = row['Instruction']
    response    = row['Response']
    return f"[INST]{instruction}[/INST]{response}"

df['Formatted'] = df.apply(format_rows, axis=1)

After formatting, each split is persisted as a CSV file and reloaded as a Hugging Face Dataset object. A histogram analysis of text lengths across splits confirmed a broadly consistent distribution, ruling out major length-based biases between splits.

IV. Model Architecture & Quantisation

The phi-2 Base Model

Microsoft's phi-2 is a 2.7 billion parameter transformer trained on a curated mixture of synthetic educational text and filtered web data. Despite its modest scale, phi-2 demonstrates strong reasoning capabilities on benchmarks, making it an attractive base for domain fine-tuning where compute is constrained.

4-bit Quantisation (QLoRA)

Loading phi-2 directly in full precision would require approximately 11 GB of VRAM. Instead, the model is loaded in nf4 (NormalFloat 4-bit) quantisation via the BitsAndBytes library, with float16 used for the compute dtype. This reduces the active memory footprint dramatically, enabling training on a single NVIDIA GPU.

bnb_config = BitsAndBytesConfig(
    load_in_4bit          = True,
    bnb_4bit_quant_type   = "nf4",
    bnb_4bit_compute_dtype= torch.float16,
    bnb_4bit_use_double_quant = False
)

LoRA Adaptation

Rather than updating all 2.7 billion parameters, LoRA (Low-Rank Adaptation) introduces a small set of trainable matrices alongside frozen base weights. The rank r=32 and scaling factor alpha=64 were chosen to balance expressiveness against parameter budget. The adapter targets the attention projection weights and feed-forward layers specific to phi-2's architecture.

peft_config = LoraConfig(
    r              = 32,
    lora_alpha     = 64,
    lora_dropout   = 0.05,
    bias           = "none",
    task_type      = "CAUSAL_LM",
    target_modules = ["Wqkv", "fc1", "fc2"]
)
※

The target modules Wqkv, fc1, and fc2 correspond to phi-2's combined query-key-value projection and both layers of its MLP block — covering the principal sites of knowledge encoding in the transformer.

The use of paged_adamw_8bit offloads optimizer states to CPU memory in a paged fashion, further reducing GPU VRAM pressure. A cosine learning rate schedule with warmup is generally preferred over a flat schedule for fine-tuning, as it avoids overshooting learned representations early in training. The best checkpoint (by validation loss) is automatically retained at training end.

VI. Evaluation — ROUGE Metrics

Evaluation was performed on 100 samples drawn from the validation set, generating completions at max_length=200 tokens and comparing against the ground-truth responses using ROUGE. ROUGE (Recall-Oriented Understudy for Gisting Evaluation) measures n-gram overlap between generated and reference text — a standard metric for summarisation and generation quality.

Results were computed across three sample sizes (1, 10, and 100 validation examples) to observe consistency as the evaluation set grows. The full scores were serialised to rouge_results_100.csv for downstream analysis. ROUGE scores, whilst widely adopted, measure surface overlap rather than semantic correctness; a future iteration of this work might supplement them with BERTScore or domain-expert human evaluation.

⚗

Resource and time constraints restricted full evaluation to 100 of the 3,000 validation samples. The primary constraint was GPU inference time per generated token at max_length=200.

VII. Inference — Base vs. Fine-Tuned

Three inference configurations were tested against the same prompt: the unmodified microsoft/phi-2 base model, a first-generation fine-tuned checkpoint, and the improved fine-tuned model with a more carefully structured prompt template.

The query used throughout was a CVE identifier lookup:

prompt = "What is the description of CVE-2012-0782?"
prompt = """
You are an expert in the field of cybersecurity.
Provide the necessary information to answer the
questions for the following CVE: CVE-2012-0782.

Response:
"""
Base phi-2

The base model produces a generic response. It may partially describe the CVE concept but tends to hallucinate specific technical details — affected software versions, patch identifiers, or CVSS scores that are fabricated rather than retrieved from its training distribution.

Fine-tuned (improved)

The fine-tuned model, given a role-contextualised prompt, produces a structured, CVE-idiomatic response. It correctly anchors to the identifier, describes the affected component, and provides a technically grounded description consistent with the NVD record format.

VIII. Deployment

The fine-tuned model and all associated training artefacts — checkpoints, training logs, configuration files — were uploaded to the Hugging Face Hub as a private repository under saikiranpennam/phi2-FT-improved-cves-data. The model shards were set to a maximum size of 7 GB to remain within Hub file size limits.

IX. Conclusion & Further Work

This pipeline demonstrates that a small, quantised language model can be efficiently adapted to a specialist cybersecurity domain using publicly available data and open-source tooling. The combination of NF4 quantisation, LoRA parameter efficiency, and a structured instruction format yields a model that responds to CVE queries in a markedly more accurate and domain-consistent manner than the base phi-2 checkpoint.

Several avenues remain open for improvement. The training sample (10,000 records) represents a fraction of the full CVE corpus; expanding this should improve recall of less-common vulnerability patterns. The evaluation metric — ROUGE — is a surface-level proxy; future work should incorporate embedding-based similarity or structured information extraction to measure factual accuracy rather than lexical overlap. Finally, the prompt template may be further refined: a few-shot format, with examples of correct CVE descriptions prepended, may improve generation quality without any additional training.

The model is available for evaluation at the above Hugging Face repository. All training code is available in the accompanying Jupyter notebook.
